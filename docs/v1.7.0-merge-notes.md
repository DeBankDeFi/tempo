### Q2: 是否在本次合并中清理 debank-rpc 既有 clippy 债务？

### Q3: tempo-e2e --lib 全套并发/串行均报 mdbx OOM，是环境问题非 v1.7.0 回归

**症状**：`cargo test -p tempo-e2e --lib` 不论并发（`--test-threads=1`）还是默认，55 个测试中前几个通过，后面全部 panic 在 `crates/e2e/src/testing_node.rs:229` ——`failed to init database: failed to open the database: Cannot allocate memory (12)`。

**已验证非回归**：
- 单测各自 `cargo test -p tempo-e2e --lib -- single_node` 等 PASS
- T4 相关单测（如 `blocks_have_consensus_context`、`consensus_context_appears_after_t4_activation`）单独跑 PASS

**根因**：macOS 上 mdbx mmap 累积资源（fd / vm mapping），跑多个 e2e 测试后无法及时释放，触发 ENOMEM。Linux CI 环境（更宽松的 vm.max_map_count）应无此问题。

**决策**：本次合并以 **单测验证为准**，不强求 e2e 全套 macOS 本地通过。CI 跑全套（`.github/workflows/test.yml` 等）才是权威。
